INTRODUCTION                                           *zj-theme-introduction*

zj-theme.nvim syncs zellij's theme — and optionally your terminal
emulator's own theme — to whatever nvim colorscheme is currently active.

Two independent channels, each on by default or opt-in:

  - zellij's own theme: rewrites zellij's config file directly. zellij
    watches that file for changes and applies them to your already-running
    session automatically (zellij polls it roughly once a second), so this
    takes effect live — no restart needed. Requires being inside a zellij
    session.
  - Your terminal emulator's theme (opt-in, see |zj-theme-terminal-theme|):
    rewrites a small file this plugin owns, which the terminal itself is
    set up to pick up live. Works whether or not you're inside zellij.

How the zellij channel works:

  1. A |ColorScheme| autocmd fires whenever you run `:colorscheme ...` (or a
     plugin sets one on your behalf).
  2. The new `vim.g.colors_name` is looked up in a mapping table (built-in
     defaults + anything you add) to find the corresponding zellij theme
     name.
  3. The `theme "..."` line in zellij's `config.kdl` is rewritten in place
     with that theme name.
  4. If any step fails — you're not inside a zellij session, the colorscheme
     has no mapping, the config file isn't readable, or it has no `theme`
     line to rewrite — it falls back to a configurable default zellij theme
     instead of leaving things inconsistent.

The terminal-theme channel follows the same shape (resolve, write, fall
back on failure) — see |zj-theme-terminal-theme|.

==============================================================================
REQUIREMENTS                                           *zj-theme-requirements*

Neovim >= 0.10, for the `vim.health.*` API used by |zj-theme-health|.

No external plugin dependency needed. The terminal-theme channel
(|zj-theme-terminal-theme|) needs the terminal emulator itself configured
to pick up the file this plugin writes — see that section.

==============================================================================
INSTALLATION                                           *zj-theme-installation*

No external plugin dependency needed — every install snippet below is
just this plugin on its own.

Works with any plugin manager. Example with lazy.nvim:
>lua
  {
    "jaimeibanezrivera/zj-theme",
    lazy = false,
    config = function()
      require("zj-theme").setup({
        -- see |zj-theme-configuration|
      })
    end,
  }
<
See the README for packer.nvim, vim-plug, mini.deps, and vim.pack examples.

==============================================================================
CONFIGURATION                                         *zj-theme-configuration*
>lua
  require("zj-theme").setup({
    -- zellij's config.kdl.
    zellij_config_path = vim.fn.expand("~/.config/zellij/config.kdl"),

    -- Fallback zellij themes, picked by vim.o.background.
    default_dark_theme = "default",
    default_light_theme = "pencil-light",

    -- nvim colorscheme -> zellij theme. Merged over mappings.lua's
    -- defaults. Value can be { dark = "...", light = "..." } for
    -- colorschemes that don't rename on background (ayu.nvim, etc).
    mappings = {
      mycustomtheme = "my-zellij-theme-name",
      myflexibletheme = { dark = "my-dark-zellij-theme", light = "my-light-zellij-theme" },
    },

    -- Terminal emulator sync — see |zj-theme-terminal-theme|. nil
    -- emulator disables it.
    terminal = {
      emulator = nil, -- "wezterm" | "alacritty"

      -- nil uses the emulator's standard config dir.
      config_path = nil,

      -- alacritty only. nil defaults to ~/.config/alacritty/themes.
      themes_dir = nil,

      -- Same shape as `mappings` above, for the terminal instead of
      -- zellij.
      mappings = {
        mycustomtheme = "My Custom Scheme",
      },

      -- Fallback themes. nil uses the emulator's own default.
      default_dark_theme = nil,
      default_light_theme = nil,
    },

    -- Silence vim.notify warnings/errors.
    notify = true,
  })
<
Your `config.kdl` needs an actual (uncommented) `theme "..."` line already
present for this plugin to find and rewrite — it won't add one from
scratch.

==============================================================================
BUILT-IN MAPPINGS                                          *zj-theme-mappings*

See `lua/zj-theme/mappings.lua` for the full zellij-theme mapping list
(catppuccin, gruvbox, tokyonight, nord, dracula, kanagawa, everforest,
solarized, ayu, onedark, and a few variants), and
`lua/zj-theme/terminals/wezterm.lua` / `lua/zj-theme/terminals/alacritty.lua`
for the same colorschemes mapped to each terminal's own theme names. These
are best-effort — override any of them via `mappings` / `terminal.mappings`
in |zj-theme-configuration|.

==============================================================================
FALLBACK BEHAVIOR                                          *zj-theme-fallback*

zellij's theme: `default_dark_theme` or `default_light_theme` (chosen by
`vim.o.background`) is used whenever:

  - nvim is not running inside a zellij session (`$ZELLIJ` unset) — no-op,
    nothing is written at all.
  - the active colorscheme has no entry in `mappings`.
  - `zellij_config_path` doesn't exist/isn't readable, or has no
    `theme "..."` line to rewrite.

Terminal emulator theme: `terminal.default_dark_theme` or
`terminal.default_light_theme` is used whenever `terminal.emulator` is set
but the active colorscheme has no entry in `terminal.mappings`, or writing
`terminal.config_path` fails (e.g. its directory doesn't exist). Nothing
is written at all if `terminal.emulator` is unset.

==============================================================================
TERMINAL EMULATOR THEME                            *zj-theme-terminal-theme*

Rewriting zellij's theme only changes zellij's own colors — borders, tab
bar, status bar. It doesn't touch your terminal emulator's own palette,
and it does nothing at all outside zellij. Setting `terminal.emulator`
turns on a second, independent channel for that.

Unlike the zellij channel, this one never touches your terminal's real
config file. Instead it writes the resolved theme into a small file this
plugin owns (`terminal.config_path`, defaulting to each emulator's
standard config dir), and your terminal's real config just needs a
one-time change to pick that file up — the same shape as the zellij
channel needing an existing `theme "..."` line to rewrite instead of
adding one from scratch.

Only terminal emulators that reload their own config live are supported,
each as an adapter under `lua/zj-theme/terminals/`. Currently:

  - "wezterm": writes `terminal.config_path` (a Lua file returning the
    resolved WezTerm scheme name; defaults to
    ~/.config/wezterm/zj-theme.lua). Your real `wezterm.lua` needs
    `config.color_scheme = require("zj-theme")` plus
    `wezterm.add_to_config_reload_watch_list(...)` on that file, since
    wezterm only auto-reloads `wezterm.lua` itself by default.
  - "alacritty": writes `terminal.config_path` (a `general.import`
    pointing at `<terminal.themes_dir>/<theme>.toml`; defaults to
    ~/.config/alacritty/zj-theme.toml). `terminal.themes_dir` defaults to
    ~/.config/alacritty/themes, expected to be a checkout of
    alacritty/alacritty-theme's themes/ folder, since Alacritty has no
    built-in named schemes. Your real `alacritty.toml` needs
    `general.import = [...]` pointing at `terminal.config_path`.

Not supported: Ghostty has no automatic file-watch config reload (only a
manual keybind/signal), so writing a file alone can't make it live; Kitty
fits in principle but its idiomatic live-switch path is a remote-control
call, not a file watch, so it isn't a drop-in adapter either. See
ARCHITECTURE.md §6.2 for details if you want to attempt either.

See the README's "Bonus: Terminal emulator theming" section for the full
setup snippets.

==============================================================================
HEALTH                                                       *zj-theme-health*

Run `:checkhealth zj-theme` to check:

  - whether `setup()` has been called
  - whether you're currently inside a zellij session
  - whether `zellij_config_path` exists and has a `theme "..."` line
  - whether the currently active colorscheme has a zellij mapping
  - if `terminal.emulator` is set: whether it names a supported adapter,
    whether `terminal.config_path` is set and its directory is writable,
    and whether the active colorscheme has a mapping for that terminal
    too (|zj-theme-terminal-theme|)
